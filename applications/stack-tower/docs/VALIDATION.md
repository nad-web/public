# Stack Tower verification

Release 1.0.0 · 8 November 2026 · Noorullah Adel

## Automated checks

**30 tests pass** using Node.js 24 without third-party runtime packages. Engine checks cover deterministic movement, axis alternation, overlap geometry and trimmed pieces in both directions, perfect scoring/streaks, narrowed tolerance on tiny blocks, complete misses, cooldown, pause/resume, fixed time steps, movement bounds, Chill parameters and bounded render history. Shared tests cover validated defaults/history, idempotent completion, mode-specific bests, stale writers, denied/full storage, preserved unreadable records and app-scoped reset. Audio tests cover opt-in, unlock/resume, mute and unsupported-platform fallback. Fullscreen tests cover native capability detection, actual success state and denied API fallback.

Six service-worker tests per game check generated bytes, integrity-checked core files, offline entry/module requests, cache readiness, failed preparation, repair, explicit update activation, different repository prefixes and preservation of other apps' caches.

The local representative repository discovers **28 independent applications**. Its source checks, **298 tests** and repository build pass with both new games included. The protected Sankey byte fixture passes. This is local integration evidence, not a live GitHub deployment.

## Browser checks

The available cloud Chromium browser was used below both `/public/applications/stack-tower/` and `/001_Public/applications/stack-tower/`.

Both games switch to a viewport-sized play screen. At **320 × 568** portrait and **780 × 390** landscape test viewports, the play screen matches the viewport, has no horizontal page overflow, and its primary controls remain inside the screen. Landscape uses a separate arrangement. Dialogs scroll within the available height. Extremely short portrait word-game viewports can scroll inside the puzzle area while the play shell stays screen-sized.

Word Scramble checks include a correct solve and clean score, revealed letters surviving Clear, hinted score deductions, five-puzzle completion, skips, Daily mode, Rush ticking/pausing, keyboard pause/resume, and typing P without triggering pause. Stack Tower checks include perfect and trimmed placements, best-height persistence, complete miss/game over, paused movement and menu/replay controls. Optional sound on/mute, settings, local records, credits and the installation guide are checked through the UI. Engine and storage tests provide additional coverage beyond these browser examples.

Native fullscreen was unavailable or denied in this browser; screen-filling viewport play and the installation-guide fallback remain functional. Fullscreen API success/denial is unit-tested with a simulated platform, not an OS installation test. The HTTP preview correctly reports that offline registration needs HTTPS or a supported browser, including after checking offline files. Offline requests are exercised in the worker test harness, not by claiming that this HTTP preview installed a worker.

## Physical-device and deployment checks remaining

Physical iPhone/iPad Safari, Android, Firefox, Edge and macOS Safari were not available for these checks. A narrow Chromium iframe is not an iPhone. Home Screen installation, native fullscreen, audible speaker output and real Airplane Mode/offline reopen must be checked after deployment on the user's devices.

1. Push both complete app folders and confirm the latest shared GitHub Pages build and publish jobs succeed.
2. Open the HTTPS address on each target browser. Check tap/keyboard input, phone rotation, pause when switching apps, and explicit resume.
3. On iPhone, use Safari → Share → Add to Home Screen → Open as Web App when offered → Add, then launch the icon. Browser bars in an ordinary tab and OS status/gesture areas are controlled by the platform.
4. Open the installed icon online until **Ready for offline play**, then reopen in Airplane Mode. Reconnect for updates. Cached files can be evicted and clearing website data removes them and local scores.
5. Toggle sound with device volume audible. Confirm a later release offers its explicit update prompt. Test other apps at their own addresses.

This targets modern browsers with ES modules, Pointer Events and Canvas where needed. Installation/Fullscreen API support varies, secure service workers require HTTPS or localhost, and every old or future browser cannot be guaranteed.
