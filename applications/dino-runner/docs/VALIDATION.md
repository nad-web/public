## Browser verification

Checked the built static output in the available cloud Chromium browser:

- Desktop rendering, original canvas artwork, jump and duck controls, pause/resume, collision/game-over and replay.
- Local best score and preferences survive reload. Colour, moonlight/daylight, sound opt-in/mute and optional-effects controls operate through the UI.
- 320-pixel portrait and 780-by-390-pixel landscape iframe viewports. Normal scrollbar space leaves 305 and 765 CSS pixels respectively; the app has no horizontal page overflow. Large JUMP/DUCK controls and 44-pixel sound/pause targets fit. Settings and installation dialogs remain within the viewport and scroll vertically.
- Phone duck toggle, mode selection and three-heart Chill display. Help, credits and installation instructions remain available at narrow widths.
- The install guide's offline check correctly reports that the HTTP preview requires HTTPS or supported browser capabilities. It does not claim a cache was prepared there.
- The score-export link has a local Blob URL and a `dino-runner-scores.json` download filename. Download receipt and file opening in a device's Files app remain manual checks; no upload/import feature is provided.

## Checks to perform after deployment

Physical iPhone/iPad Safari, Android, Firefox, Edge, macOS Safari and OS-level installation were not available for this verification. A narrow Chromium viewport is not a physical-device test.

On your deployed HTTPS address, check:

1. The latest GitHub Pages build and publish jobs succeed; open `/public/applications/dino-runner/`.
2. Play with keyboard and touch on your actual browsers. Check held jump, short hop, duck, pause, device rotation and app background/resume.
3. Enable and mute sound with the device's volume audible. Silent-mode and browser policies may still suppress it.
4. Wait for **Ready for offline adventures**, add the app to Home Screen, open the installed icon online once, then reopen it in Airplane Mode. Repeat after an update and after browser data is cleared if offline readiness matters.
5. Download the score JSON, open it in Files/Downloads, and retain it if wanted. It is a readable export, not an import/restore file.
6. Check the explicit update prompt on a later release, and that other apps still work at their own addresses.

The app is designed for modern browsers using Canvas, ES modules, Pointer Events and Web Audio. Offline support requires service workers in a secure context; installation is browser/OS dependent. Every past or future browser, assistive technology and device cannot be guaranteed. Essential obstacle motion requires visual timing even when optional effects are disabled.
