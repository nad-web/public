The browser preview is HTTP on a non-localhost hostname. It correctly reports that HTTPS or a supported secure context is required for offline setup. It cannot establish actual HTTPS worker installation, Home Screen installation or Airplane Mode playback. Automated worker tests are separate evidence, not physical-device tests.

**Pending:** physical iPhone/iPad Safari and installed-app tests; native desktop Safari, Firefox and Edge; actual browser-native installation prompts; device audio output, VoiceOver and long-term storage retention. The timing course is visual; semantic menus/controls do not make it a fully nonvisual game. No guarantee of support in every historical browser or permanent unevictable offline storage is made.

After deployment on your HTTPS URL, open from each intended browser/device, play a run, check jumps, fish sounds, pause/resume, saved scores and download behavior. Install where supported, open the new icon online until ready, close it, enable Airplane Mode and reopen. Test an update and confirm another application's cache is preserved. Browser/installed-app profiles can hold separate local records.

Repeat with Node 24+: `node scripts/check.mjs` and `node --test tests/*.test.mjs`. After changing runtime files, run `node scripts/update-cache.mjs` first. The included ready-to-upload worker already matches the delivered runtime files.
